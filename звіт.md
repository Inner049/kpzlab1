## ПР-8: ПОРОДЖУЮЧІ ПАТЕРНИ ПРОЕКТУВАННЯ

### Мета роботи
Реалізувати три породжуючі патерни (Singleton, Factory Method, Builder) у контексті проєкту Expense Tracker.

### Виконані завдання

#### 1. Singleton — конфігурація застосунку

**Файл:** [`src/core/config.py`](src/core/config.py)

**Реалізація:**
- Thread-safe Singleton з використанням `threading.Lock()`
- Метод `load()` завантажує конфігурацію лише один раз
- Підтримка змінних оточення (DEBUG, DB_URL, SECRET_KEY, LOG_LEVEL)

**Ключові особливості:**
```python
class AppConfig:
    _instance = None
    _lock = threading.Lock()
    
    def __new__(cls):
        with cls._lock:
            if cls._instance is None:
                cls._instance = super().__new__(cls)
                cls._instance._loaded = False
        return cls._instance
```

**Тестування:** [`tests/test_config.py`](tests/test_config.py) — перевірка що `cfg1 is cfg2` повертає `True`.

#### 2. Factory Method — фабрика звітів

**Файл:** [`src/patterns/report_factory.py`](src/patterns/report_factory.py)

**Реалізовані генератори звітів:**
1. `CSVReportGenerator` — генерація CSV звітів
2. `PDFReportGenerator` — генерація PDF звітів
3. `JSONReportGenerator` — генерація JSON звітів

**Розширюваність (OCP):**
Фабрика підтримує динамічну реєстрацію нових типів через метод `register()`:
```python
ReportFactory.register("excel", ExcelReportGenerator)
report = ReportFactory.create("excel")
```

#### 3. Builder — конструктор витрат

**Файл:** [`src/patterns/expense_builder.py`](src/patterns/expense_builder.py)

**Можливості:**
- Fluent Interface (ланцюжок викликів)
- Валідація даних (сума > 0)
- Підтримка тегів та опису

**Приклад використання:**
```python
expense = (ExpenseBuilder()
    .amount(1450.50)
    .category(2)
    .date(date.today() - timedelta(days=1))
    .description("Закупівля продуктів")
    .tag("їжа")
    .build())
```

### Завдання для закріплення

#### 8.1 A: Thread-safe Singleton
✅ **Виконано** — реалізовано з використанням `threading.Lock()` у [`src/core/config.py`](src/core/config.py:10)

#### 8.1 B: Пояснення відмінності від Singleton
**Відповідь:** Наведений у завданні код НЕ є Singleton, оскільки він не обмежує створення нових екземплярів класу. Кожен виклик `Config()` створює новий об'єкт у пам'яті (тому `c1 is c2` повертає `False`). Використання спільної змінної класу (`data`) робить стан об'єктів спільним, але це патерн **Monostate (Borg)**, а не Singleton. Справжній Singleton гарантує існування лише одного екземпляра класу.

#### 8.2: Розширення Factory без зміни коду
✅ **Виконано** — продемонстровано у [`demo/patterns_demo.py`](demo/patterns_demo.py:22-26):
```python
class ExcelReportGenerator(ReportGenerator):
    def generate(self, data: list) -> str:
        return f"Згенеровано EXCEL звіт для {len(data)} записів."

ReportFactory.register("excel", ExcelReportGenerator)
```

## ПР-9: ПОВЕДІНКОВІ ТА СТРУКТУРНІ ПАТЕРНИ

### Мета роботи
Реалізувати Observer, Strategy, Decorator та Facade у контексті проєкту.

### Виконані завдання

#### 1. Observer — система подій (EventBus)

**Файл:** [`src/patterns/event_bus.py`](src/patterns/event_bus.py)

**Реалізація:**
- Централізована шина подій (Event Emitter pattern)
- Методи `on()` для підписки та `emit()` для сповіщення
- EventBus сам є Singleton для зручності

**Реалізовані спостерігачі (мінімум 3):**
1. `log_expense()` — логування витрати
2. `check_budget()` — аналіз бюджету
3. `send_alert()` — сповіщення про великі витрати (>1000 UAH)

**Приклад використання:**
```python
bus = EventBus()
bus.on("expense.added", log_expense)
bus.on("expense.added", check_budget)
bus.emit("expense.added", {"amount": 1500, "category": "Техніка"})
```

#### 2. Strategy — стратегії звітів

**Файл:** [`src/patterns/expense_strategy.py`](src/patterns/expense_strategy.py)

**Реалізовані стратегії (мінімум 3):**
1. `TotalSumStrategy` — загальна сума витрат
2. `CategorySumStrategy` — сума по категоріях
3. `AverageExpenseStrategy` — середній чек

**Strategy + Factory (Завдання 9.2):**
```python
class StrategyFactory:
    @classmethod
    def create(cls, strategy_name: str) -> ReportStrategy:
        # Повертає потрібну стратегію за назвою
```

#### 3. Decorator — кешування та вимірювання часу

**Файл:** [`src/core/decorators.py`](src/core/decorators.py)

**Реалізовані декоратори (мінімум 2 + бонус):**
1. `@timer` — вимірювання часу виконання функції
2. `@cache` — кешування результатів
3. `@retry(times=3)` — перезапуск при помилці (бонус)

**Застосування:**
```python
@timer
@cache
def expensive_calculation(x):
    return x * x
```

#### 4. Facade — спрощення роботи з підсистемами

**Файл:** [`src/patterns/expense_facade.py`](src/patterns/expense_facade.py)

**Інтегровані сервіси (мінімум 3):**
1. `DatabaseService` — збереження в БД
2. `NotificationService` — відправка push-сповіщень
3. `AnalyticsService` — трекінг подій
4. `EventBus` — тригер Observer-ів

**Метод фасаду:**
```python
@timer
@retry(times=2)
def process_new_expense(self, amount: float, category: str):
    self.db.save(expense_data)
    self.notif.send_push(f"Витрачено {amount} UAH")
    self.analytics.track("expense_created")
    self.bus.emit("expense.added", expense_data)
```

**Файл:** [`src/services/expense_calculator.py`](src/services/expense_calculator.py)

**Функція:** `calculate_monthly_total()` — обчислює загальну суму витрат за місяць

**TDD цикл (3 коміти):**

   ```bash

   ```

2. **🟢 GREEN коміт:**
   ```bash
   git commit -m "feat: GREEN - мінімальна реалізація calculate_monthly_total"
   ```
   - Створив функцію з мінімальною реалізацією
   - Всі 6 тестів пройшли

3. **♻️ REFACTOR коміт:**
   ```bash
   git commit -m "refactor: REFACTOR - покращення calculate_monthly_total"
   ```
   - Додав type hints
   - Використав list comprehension
   - Покращив читабельність

**Фінальна реалізація:**
```python
def calculate_monthly_total(user_expenses: List[Dict[str, Any]], month: int, year: int) -> float:
    """Обчислює загальну суму витрат за місяць"""
    if not 1 <= month <= 12:
        raise ValueError("Місяць має бути від 1 до 12")
    
    return sum(
        expense["amount"]
        for expense in user_expenses
        if expense["date"].month == month and expense["date"].year == year
    )
```
